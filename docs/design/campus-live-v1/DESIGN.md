# Campus Live V1 · 东大主场

状态：设计评审稿，等待用户确认。这里是可浏览的高保真静态方案，不是已实现的 Vue 客户端；不请求生产接口、不更改当前服务。2026-09-13。

## 1. 产品结构与信息架构

核心路径是「发现正在发生的比赛 → 进入直播间 → 比赛结束后看回放」。用校园归属感连接内容，但视频始终是主角。

| 页面 | 最重要的问题 | 首要动作 | 其他内容 |
| --- | --- | --- | --- |
| 首页 `/` | 东大现在有什么比赛？ | 进入重点直播 | 其他直播、可用时显示的近期赛事、精选回放 |
| 直播列表 `/live` | 哪场正在直播？ | 按项目筛选并进入频道 | 待开播频道、空状态、数据更新提示 |
| 直播详情 `/live/:id` | 能否尽快看到比赛？ | 播放/重连 | 场地、参赛双方、赛事简介、相关回放 |
| 点播列表 `/vod` | 能找到想看的比赛吗？ | 搜索、筛选、打开视频 | 标题、项目、简介、时长、发布时间 |
| 点播详情 `/vod/:id` | 这是什么比赛，如何继续看？ | 播放/暂停/拖动 | 完整简介、来源信息、同类视频 |

导航只保留首页、赛事直播、精彩回放。暂不出现空的球队、收藏、个人中心和排行榜入口。搜索默认进入点播搜索结果；只有后续全局搜索可查真实赛事后，才合并直播/赛事结果。

## 2. 视觉方向与选择理由

方向名：「东大主场」。它是面向学生的体育媒体产品，采用暖白浏览底色、深墨播放场景、松青品牌主色和暖金动作强调。

- 暖白内容区降低长时间浏览的视觉负担，也让照片成为信息重心。
- 直播 Hero 和播放页采用深色，使“现在发生的比赛”有明确的视觉优先级。
- 照片负责体育氛围，字号、留白和分隔线负责层级。不依赖大量渐变、发光和悬浮卡片。
- 大尺寸封面 + 开放式标题用于内容库；细分隔线赛事行用于近期内容；深色播放器承载观看。不同信息使用不同形态。
- 统一原创 Campus Live 字标与 C/前进方向标记，校名以「东南大学 · 学生体育」作为语境，不把产品包装成学校官方转播机构。

## 3. 东南大学元素：依据与落点

| 元素 | 官方依据 | 设计落点 |
| --- | --- | --- |
| 黄、绿的校标色彩语义 | [东南大学校标释义](https://www.seu.edu.cn/2023/0527/c47313a446813/page.htm)：黄色、绿色；绿色与青年学子和六朝松联系 | 松青主色与少量暖金强调；本文色值为自定义产品色，非校方标准色值 |
| 四牌楼大礼堂 | 同一校标释义说明该建筑是标志性建筑 | 原创穹顶、山花与柱廊意象线稿，用于品牌底部和缺图封面，不临摹或改造学校圆形校标 |
| 校训「止于至善」 | [校史馆：校训、校风](https://history.seu.edu.cn/18738/list.htm) | 普通正文字体用于页脚和品牌语境；「热爱在场」是产品自拟文案，并非校训组成部分 |
| 九龙湖、四牌楼的校园记忆 | [校友总会校园介绍](https://seuaa.seu.edu.cn/2016/0830/c12785a165606/page.psp) | 首页校园语境和品牌叙事，不把校园建筑照片当成真实赛事现场 |
| 九龙湖体育馆、桃园田径场 | [体育系联系方式](https://tyx.seu.edu.cn/2160/list.htm)、[校园入学指南](https://physics.seu.edu.cn/2022/1005/c23177a422325/pagem.htm) | 示例场馆文案；正式显示依赖赛事实际场地数据 |
| 计算机、信息、土木、建筑、经管等学院 | [学校院系设置](https://www.seu.edu.cn/2023/list.htm) | 示例对阵采用院系语境；比赛、对阵、日期与时长均属设计虚构，不声称活动实际存在 |

不直接嵌入学校标准校徽，也不将原创建筑线稿称为校徽。预览用照片为 AI 生成的普通大学篮球比赛示意，明确不是东大场馆实拍。未来真实封面应由团队提供或来自可使用的赛事资料。

## 4. 首页布局

Desktop 1440：页面左右各 48 px，中央内容宽 1344 px 内；常规内容 max-width 1328 px。顶栏 88 px，下方约 100 px 的标题区。

1. 顶栏：Campus Live + 东南大学学生体育语境、三个一级导航、简洁搜索。
2. 当前标题：「东大此刻，正在上场。」只有几个关键词强调，不占据整个首屏。
3. 核心区域：左侧约 3/4 为重点直播，420–456 px 高；右侧约 1/4 为主场速览。重点直播包含 LIVE、项目、双方、场地和唯一主 CTA。
4. 体育项目快捷入口：紧凑横向标签，帮助主动寻找内容。
5. 往期内容：四列 16:9 视频封面，不用文件大小作为视频主要信息。
6. 品牌收尾：大礼堂建筑意象、校训语境，低对比度呈现，不与比赛争夺注意力。

有真实直播优先显示直播；没有直播则转为“此刻休息，热爱不散场”与真实回放入口。近期赛程缺失时整块隐藏，主场速览只显示其他真实直播/待开播频道，不能填充虚构时间。只有一条真实直播时，不复制三条来撑满页面。

## 5. 直播页布局

列表：标题、实时状态数量、体育项目筛选、只看直播中；三列直播封面。LIVE 使用红底白字，待开播用中性色，服务查询失败使用明确的未知状态，不能视为停播。

直播间：深墨背景承载 16:9 大播放器，占主体约 75%–80%；右侧窄栏是安静的比赛信息。视频上方放返回入口与状态，下方放标题、简介，再向下才是相关推荐。没有弹幕、排行榜、礼物栏或无功能的工具按钮。

比分不是当前 MVP 必填项：没有真实比分来源时不显示数字。参赛方已知才展示双方，未知时只显示标题与场地。播放状态包括连接中、未开播、正在播放、缓冲中、断流重连、恢复失败和格式不支持，保留手动重试及键盘可操作性。

## 6. 点播页布局

列表：编辑式标题与搜索、体育类别、排序、内容结果数量，然后是四列媒体网格。卡片封面 16:9，下方按项目/类型、标题、简介、发布日期排列；时长覆盖在封面右下角。没有观看量来源时不使用“热门”排序或虚构计数。

详情：播放器仍然最大，侧边放最多两条“接着看”；下方是完整标题、发布日期、场地、简介与相关推荐。播放使用真实 video 能力，不在 MVP 伪造不存在的清晰度切换、字幕或下载功能。

## 8. 关键组件与状态

- `AppHeader` / `AppFooter`：导航、品牌、搜索、当前页语义。
- `FeaturedLive`：照片层、状态、对阵、场地、播放入口；无直播时使用专门状态布局。
- `LiveBadge`：live / offline / unknown，文字与颜色一一对应。
- `MatchRow`：紧凑赛事行，主要用于可用的赛程或其他频道。
- `SportFilter` / `CatalogToolbar`：搜索、项目、排序、清空条件；使用可访问按钮和 label。
- `VideoCover`：真实封面 → 自定义校园/运动场线稿 fallback，保持固定比例，避免布局跳动。
- `VideoCard`：内容库统一媒体结构，不承载播放器职责。
- `LivePlayer` / `VodPlayer`：复用 video 外壳，分别隔离 HLS 生命周期与原生点播行为。
- `MatchSummary` / `VideoMetadata`：数据存在才显示，不从文件名猜比分、时间、双方。
- `LoadingState` / `EmptyState` / `ErrorState`：骨架占位、无直播、无内容、搜索无结果、网络异常、404；状态与行动都明确。
- `RelatedVideos`：优先匹配已知项目，其次已有内容，排除当前项、去重；数量不足不补假内容。

评审工具栏只属于本静态预览，正式产品不会出现“示例/设计系统”工具。预览播放器用明确说明代替假装能播放的按钮；正式 Vue 版本需要原生控件与真实 HLS 生命周期。

## 9. 响应式与可访问性

- ≥1440：左右 48 px，内容有上限；首页重点直播 + 速览，点播 4 列。
- 1024–1439：左右 32–48 px，侧栏缩窄、点播 3–4 列，播放器仍优先。
- 768–1023：Hero 与速览纵向组织，点播 2–3 列；比赛信息移到视频下方，避免横向挤压。
- <768：左右 20 px；直播 1 列，点播 2 列，小屏搜索下移为内容搜索；不会保留空白侧栏。
- 使用语义标题、跳到正文、可见 focus、aria-current、明确 input label；切换路由后管理页面标题与焦点，错误区域使用适当 live region。参考 [Vue 官方可访问性指导](https://vuejs.org/guide/best-practices/accessibility.html)。
- 主要动画尊重 `prefers-reduced-motion`；直播不强制有声自动播放。

## 10. 与现有 API 的落地边界

现有前端是 React；本轮只新增设计材料。确认后迁移到 Vue 3 + Vite + TypeScript + Vue Router + hls.js，不修改 FastAPI/SRS/Nginx 的接口语义。

| 展示字段 | 当前来源 | 正式版本策略 |
| --- | --- | --- |
| 直播 ID、标题、项目、场地、状态、播放地址 | `/api/live`、`/api/live/:id` | 直接经适配层映射，保留超时、错误与状态更新 |
| 视频 ID、文件名、标题、地址 | `/api/vod`、`/api/vod/detail?filename=…` | 使用现有接口，保持百分号文件名回归 |
| 封面、简介、分类、参赛方 | 当前没有完整来源 | 建立独立、类型完整的可选编辑信息映射，用实际媒体 ID 匹配；缺项用真实默认值/占位。配置不与组件混写 |
| 时长 | API 未提供 | 播放页 `loadedmetadata` 可获取；列表只显示已知编辑信息或“时长待补充”，不预加载全部媒体来凑时长 |
| 发布时间 | API 未提供 | 有实际元数据才显示；缺失显示“发布时间待补充”，不能用文件名顺序伪装最新 |
| 赛程、比分、收藏、热度 | API 未提供 | 暂不启用；本预览的赛程用于展示有数据后的布局 |

没有编辑信息时依然交付完整、诚实且美观的界面。需要添加来源时使用可选配置而不是随意扩改后端。

## 11. Vue 实施计划（确认后执行）

```text
apps/web/src/
  app/             # App.vue, router, 全局样式入口
  api/             # 原有接口契约、fetch、超时和错误
  domain/          # DTO、ViewModel、数据适配与筛选
  content/         # 按真实 ID 映射的可选编辑资料，示例隔离
  composables/     # useLiveCatalog, useVodCatalog, useHlsPlayer
  components/
    layout/        # Header, Footer, PageContainer
    media/         # Cover, VideoCard, Players
    events/        # FeaturedLive, MatchRow, LiveBadge
    feedback/      # Loading, Empty, Error
  pages/           # 五个核心页面 + NotFound
  styles/          # tokens.css, base.css, utilities.css
```

不采用 Element Plus，不引入庞大的后台 UI 套件；使用少量自研组件、语义 HTML 和共享 CSS Tokens。Vue Router 懒加载播放页；不因迁移丢掉重连、取消请求、卸载清理和特殊文件名处理。完善 ESLint + Vue 插件、vue-tsc、Vitest + Vue Test Utils、Playwright。

按「基础设计系统 → 列表与首页 → 播放页 → 响应式与无障碍 → 真实 API 联调」交付；运行 lint、typecheck、build、单元测试、浏览器测试，复验 RTMP→HLS 和点播 Range/暂停/拖动。全部通过后提交代码，保持当前可运行版本可回退。

## 12. 当前评审物与下一步

打开 `index.html` 可查看五个页面、设计系统和空/错误状态；设计底部工具栏用于切换。素材和文件均本地化，无外部图片依赖。设计确认重点是：暖白+松青+暖金方向、东大元素的克制程度、首页重点直播与右侧速览的比例、播放器与信息的主次关系。

按用户要求，本阶段等待设计确认；尚未修改 `apps/web`，也尚未进行 Vue 迁移。

参考产品结构：[Red Bull 官方直播栏目](https://www.redbull.com/int-en/live-events/)的直播/回看分流，以及 [Olympic Channel 官方介绍](https://support.olympics.com/hc/en-gb/articles/1500009814861-What-is-Olympic-Channel)的体育项目发现思路。只借鉴组织方式，不复制品牌、界面或内容。
